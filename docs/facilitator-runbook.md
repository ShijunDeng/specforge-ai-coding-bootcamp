# 讲师授课 Runbook

## 课前 3-5 天

- 确认学员名单、角色和是否承担团队复讲任务。
- 发送课前准备清单，要求学员完成 spring-petclinic 本地运行截图。
- 要求学员提前 Clone dolphin-scheduler，并完成依赖下载和 IDE 索引。
- 确认 CodeAgent、AgentCenter、MCP、Skill、CodeWiki、PKIToken 的授权入口仍然有效。
- 准备演示分支，确保演示代码不含真实 Token、AK/SK 或生产地址。

## 课前 1 天

- 运行 `npm run validate` 和 `npm run generate`。
- 用 `npm run slides` 预览关键页：课程地图、第一课演示、第二课 SDD、评分 Rubric。
- 准备常见环境问题 FAQ：JDK、Maven/Gradle、代理、依赖源、Token 权限。
- 安排助教分工：环境阻塞、实操答疑、证据收集、时间提醒。
- 准备 CodeWiki 不稳定时的脱敏查询结果备份。

## 7 小时现场节奏

- 30 分钟：课程定位、工具矩阵、课堂契约。
- 60 分钟：AI Coding 演进、方法选择、上下文工程、Skill 契约。
- 95 分钟：Petclinic Owner 演示、Pet 疫苗字段练习、单测修复。
- 65 分钟：MCP 建单、机器检视、自动修复演示与练习。
- 80 分钟：复杂存量项目风险、CodeWiki 查询、SDD 四阶文档。
- 75 分钟：SMN 文档实操、AK/SK 安全红线、Tasks Review。
- 15 分钟：大作业规则、评分 Rubric、团队复讲。

## 第一课必须显式展示

- 采纳代码前先 Review diff。
- 测试失败时把错误输出交给 AI 修复。
- 提交 MR 前检查 Git 状态。
- 触发检视后根据机器意见修复，而不是手动绕过流程。
- 所有真实 Token 使用占位符或脱敏方式展示。

## 第二课必须显式展示

- 先问 CodeWiki “现有系统怎么做”，再让 AI 写文档。
- 用具体缺口打回 Design，例如“缺少 AK/SK 安全设计”。
- 检查 Tasks 是否细到类名、配置文件和测试命令。
- 把文档 Review 结论写回任务清单。
- 在 SMN 练习中禁止生成 Java 业务代码。

## 现场异常处理

- 环境失败：助教处理，不拖慢主线；必要时安排旁听和课后补跑。
- Token 失败：使用预置截图或脱敏录屏继续讲流程，课后处理账号。
- CodeWiki 不稳定：使用提前准备的查询结果样例，保留“查询问题设计”的教学重点。
- AI 输出偏航：直接展示如何打回、缩小上下文、增加验收条件。
- 时间不足：优先保留 Review 和验证动作，减少工具背景介绍。

## 课后验收

- 收集学员 MR、四阶文档、测试截图或日志、检视意见和修复记录。
- 按 `rubrics/homework-rubric.md` 评分。
- 安全红线问题必须返工：真实密钥、敏感日志、生产地址、绕过 Review 直接合并。
- 选取优秀作业和典型失败案例，脱敏后更新到下一版课程 Spec。

## 复讲建议

学员回团队复讲时，不应原样照搬所有示例。推荐保留方法论主线，替换为本团队仓库、规范和真实痛点：

- 用团队自己的小需求替换 Pet 练习。
- 用团队自己的 MR 流程替换 MCP 演示细节。
- 用团队真实存量模块替换 SMN 练习，但保留 SDD 四阶文档结构。
