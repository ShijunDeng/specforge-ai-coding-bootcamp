# 提示词样例

这些样例用于讲师演示“如何给 AI 正确上下文、约束和验收”。样例中的文件名、接口名、Token 和密钥均为占位信息，上课前需替换为脱敏演示环境。

## 1. 小范围功能开发

```text
你现在只关注我选中的 OwnerController、OwnerRepository 和对应测试文件。

需求：为 Owner 增加按姓名片段模糊查询的能力。

约束：
- 先不要修改数据库 schema。
- 不要改无关页面和配置。
- 先输出改动计划，列出准备修改的类和方法。
- 计划经我确认后再改代码。

验收：
- 正常查询能返回匹配 Owner。
- 空查询和无匹配结果要有明确行为。
- 补充或更新单测，沿用项目现有测试风格。
```

## 2. 采纳前 Review

```text
请基于当前 diff 做一次采纳前 Review。

重点检查：
- 是否修改了需求之外的文件。
- 查询语义是否和需求一致。
- 空值、大小写、分页或排序是否存在遗漏。
- 新增测试是否真正验证业务行为，而不是只有空断言。
- 是否引入日志、异常处理或性能风险。

请按“必须修复 / 建议调整 / 可以接受”三类输出。
```

## 3. 测试失败后修复

```text
以下是本地测试失败输出。请先判断失败原因，再给最小修复方案。

限制：
- 优先修复业务代码或测试断言中的真实问题。
- 不要删除测试来让构建通过。
- 不要扩大修改范围。

失败输出：
<粘贴脱敏后的测试失败日志>
```

## 4. MCP 建 MR

```text
请通过已配置的 CodeHub MCP 为当前分支创建 MR。

MR 要求：
- 标题格式：[AI-Coding-Lab] Pet vaccine field
- 描述包含需求、改动摘要、测试命令和测试结果。
- 不要在描述中包含 Token、账号、内部密钥或生产地址。
- 创建前先展示将要提交的文件列表和 MR 描述草稿，等我确认后再执行。
```

## 5. 检视意见修复

```text
请读取当前 MR 的机器检视意见，并按意见生成修复计划。

要求：
- 先按严重程度分组。
- 每条意见说明对应文件、风险和修复方式。
- 经我确认后再改代码。
- 修复后运行相关测试，并输出验证命令。
```

## 6. CodeWiki 探查存量项目

```text
请基于 CodeWiki 查询 dolphin-scheduler 现有告警插件机制。

我需要你重点回答：
- 现有告警插件有哪些实现类和注册方式？
- 配置项如何声明、校验和传递？
- 发送失败、超时、错误日志如何处理？
- 现有测试样例在哪里？
- 新增插件时最容易违反哪些项目约束？

请不要生成 Java 业务代码，只输出事实、引用位置和后续设计影响。
```

## 7. 生成 SDD 四阶文档

```text
基于刚才的 CodeWiki 查询结果，请为“新增 SMN 告警插件”生成四阶 SDD 文档。

输出四个部分：
1. Proposal：目标、范围、非范围、风险。
2. Spec：可验收行为和验收标准。
3. Design：接入架构、配置模型、AK/SK 安全设计、错误处理、测试策略。
4. Tasks：按具体类名、配置文件、测试文件和验收命令拆分。

限制：
- 禁止生成 Java 业务代码。
- AK/SK 必须通过配置注入，不能硬编码。
- 日志和异常不得输出完整密钥。
- Tasks 必须能逐项交给 Agent 执行和人工验收。
```

## 8. 打回不合格设计

```text
这版 Design 不合格，请基于以下缺口重写相关章节，不要重写无关内容。

缺口：
- 没有说明 AK/SK 的配置来源、校验和脱敏。
- 没有说明发送失败、超时和重试策略。
- Tasks 没有细化到具体类名和测试文件。
- 缺少与现有告警插件接口的对齐说明。

请输出修订后的 Design 片段和 Tasks 片段，并标注你修复了哪些问题。
```
