# 脱敏提示词样例

以下样例用于课堂演示和学员练习。所有仓库地址、Token、AK/SK、内部域名都应在真实使用前替换为脱敏占位符。

## Petclinic 功能微改

```text
目标：为 Pet 增加疫苗接种记录字段和按疫苗名称查询能力。

上下文：我已经选中了 Pet 实体、PetController、相关 Repository 和现有测试文件。

边界：
- 先输出修改计划，不要直接改代码。
- 只修改与 Pet 字段、查询接口和测试相关的文件。
- 保持项目现有命名和测试风格。

输出：
- 给出计划后等待我确认。
- 确认后生成候选补丁和对应单测。

验收：
- 指定需要运行的测试命令。
- 解释你新增的断言覆盖了哪些业务行为。
```

## 测试失败修复

```text
下面是我运行测试的命令和失败输出。请先定位失败原因，再给最小修复方案。

约束：
- 不要扩大修改范围。
- 不要删除已有断言来让测试通过。
- 修复后说明需要重新运行哪个命令。

测试命令：
<粘贴命令>

失败输出：
<粘贴关键堆栈和断言失败信息>
```

## MCP 建单

```text
请基于当前分支通过 MCP 创建 MR。

约束：
- 目标仓库和目标分支请先复述给我确认。
- MR 描述需要包含需求、变更文件、测试命令和风险。
- 不要在 MR 描述中写入 Token、内部生产地址或真实凭证。
- 创建前先检查工作区状态。
```

## CodeWiki 查询

```text
请查询当前 dolphin-scheduler 仓库中告警插件的扩展机制。

我需要的信息：
- 现有告警插件入口类或注册机制。
- 配置模型和校验逻辑。
- 发送失败、超时、异常日志的处理方式。
- 现有插件的测试样例。
- 凭证类配置是否有脱敏规范。

输出要求：
- 不要生成业务代码。
- 按“事实、来源、对 SMN 设计的影响”整理。
```

## SDD 文档打回

```text
请修订刚才生成的 Design。

打回原因：
- 缺少 AK/SK 配置注入和日志脱敏设计。
- Tasks 没有细化到类名、配置文件和测试。
- 没有说明发送失败和超时如何处理。

要求：
- 基于前面 CodeWiki 查询到的现有插件规范修订。
- 不要生成 Java 业务代码。
- 输出修订后的 Design 摘要和 Tasks 变化清单。
```
