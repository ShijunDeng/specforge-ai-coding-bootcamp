# 课程润色迭代记录

本记录用于说明 7 小时 AI Coding Bootcamp 课程内容的润色方向。每轮修改都围绕一个可验证目标：让页面更适合直接面向学员讲授，减少抽象总结，增加实例、证据和动态视觉。

参考的课程组织方式来自 GitHub 上较受欢迎的开源课程材料：每节课有清晰目标、可运行代码、练习任务、视觉材料和延伸路径。本课程不复制任何外部课程正文，只吸收“以项目和证据组织教学”的设计方法。

## 10 轮迭代

| 轮次 | 目标 | 已落地修改 |
| --- | --- | --- |
| 1 | 课程主线从“讲 AI Coding”改成“跟一名工程师完成可提交需求”。 | `specs/course.yaml` 增加贯穿故事：Owner 查询、测试失败、MR 打回、SMN 设计和团队推广。 |
| 2 | 开场页从概念判断改成真实冲突。 | `00-orientation.md` 用 Owner 查询的一次合并和一次拒绝，解释 AI Coding 为什么需要工程化。 |
| 3 | 工具页从罗列工具改成课堂接力。 | `00-orientation.md` 增加工具交接、输入输出证据和 7 小时路线图。 |
| 4 | 视觉风格从静态文档感改成课堂演示感。 | `style.css` 更新多色调色板、媒体边框、动态扫描线和更清晰的示例区。 |
| 5 | 图示从静态结构图改成动态演示图。 | `assets/demos/*.svg` 全部补充动画元素，覆盖 37/37 个媒体资产。 |
| 6 | 工具基础模块增加失败与修复。 | `10-foundations-tools.md` 用“大 diff、提示契约、Skill 打回弱测试”讲上下文和工具边界。 |
| 7 | Petclinic 微闭环增加运行现场。 | `20-petclinic-micro-loop.md` 用红灯、黄灯、绿灯、Review 暂停点讲小步开发。 |
| 8 | MCP/Review 模块增加权限和缺陷案例。 | `30-mcp-review-repair.md` 用平台门禁、Token 白名单、机器检视和故意埋 bug 讲安全闭环。 |
| 9 | SDD/CodeWiki 模块改成老项目探险叙事。 | `40-sdd-codewiki.md` 用“老城地下管线”“四道闸门”“问老员工”解释 Brownfield 设计。 |
| 10 | SMN 和验收模块从规则说明改成证据交付。 | `50-smn-design-lab.md`、`60-assessment-rollout.md` 用需求现场、冻结工单、MR 证据台和复讲迁移串联收尾。 |

## 后续 Review 标准

- 每页至少有一个具体例子，例子应包含场景、常见失败、修复动作或可见证据。
- 每页优先配运行画面、终端、IDE diff、MR 检视、自动验收看板或动态 SVG/GIF。
- 可见正文直接对学员说话，不出现“让学员”“讲师要”等后台语言。
- `Illustration Brief` 和 `Layout Contract` 要足够具体，降低不同 PPT 工具生成时的随机性。
- 修改 Spec 后必须运行 `npm run validate`；正式交付前运行 `npm run check`。
