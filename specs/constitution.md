# 课件工程宪法

## 原则

1. Spec 是唯一源文件。Slidev Markdown、PDF、PPTX、静态站点都是临时生成物。
2. 课程事实写入 `specs/course.yaml` 和 `specs/modules/*.md`，不要直接维护 `build/` 或 `dist/`。
3. 每个模块必须说明教学意图、学习产出、来源大纲行、逐页内容和讲师备注。
4. 每个实操任务必须有约束和验收标准，不能只写操作步骤。
5. 涉及 Token、AK/SK、内部地址、生产数据和账号权限的内容必须脱敏。

## 变更门槛

- 小改：修正文案、补充讲师备注、调整单页顺序，可直接修改模块 Markdown，并运行 `npm run validate`。
- 中改：新增章节、改变实操任务、改变 deck 组合，需要同步更新 `specs/course.yaml`、练习说明和 Runbook。
- 大改：改变课程目标、目标学员、评分规则、生成管线，需要先更新 `specs/course-production/` 四阶文档。

## 质量标准

- 标题回答“这页讲什么”，Headline 回答“这页的核心判断是什么”。
- Key Points 不超过 5-6 条，避免把讲稿塞成大段文字。
- Speaker Notes 必须能帮助讲师讲清追问、常见偏差和现场处理方式。
- Lab 页面必须包含任务、边界、验收和证据。
- 生成脚本必须支持章节组合，不能把“全量课件”写死为唯一输出。

## 交付边界

- 可以临时导出 PDF/PPTX 给课堂或归档使用。
- 不把导出的 PDF/PPTX 作为 Review 对象；Review 对象是 Spec。
- 不在仓库中提交真实外部项目源码，只提供练习说明和仓库准备要求。
