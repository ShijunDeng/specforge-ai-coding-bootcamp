# Spec: 课程材料需求规格

## 受众

首期受众是核心项目 Committer 和技术骨干。他们已经熟悉常规研发流程，需要学习如何把 AI 工具纳入现有工程治理，并承担课后在团队内复讲和推广的责任。

## 学习成果

学员完成课程后应能做到：

- 把需求拆成 AI 可执行的小任务，并用测试、MR、检视意见形成证据链。
- 使用 CodeAgent 精准提供上下文，避免无边界全仓扫描和幻觉输出。
- 调用 Skill 完成高频流程，例如生成单测、代码检视和检视意见修复。
- 配置和使用 MCP 完成外部系统动作，并理解权限、审计和人工确认边界。
- 使用 CodeWiki 探查存量项目约束，再用 SDD 输出 Proposal、Spec、Design、Tasks。
- Review AI 输出中的架构遗漏、安全遗漏和测试遗漏，并用明确反馈打回重写。

## 课程结构

- 课前准备：环境、代码仓、Token、依赖预热和运行验收。
- 第一课：基础工具跑通与开发微闭环，约 95 分钟。
- 第二课：复杂存量项目降维与 SDD 架构拆解，约 90 分钟。
- 课后：SMN 告警大作业验收、代码 Review 和问卷反馈。

## 材料形态

课程材料应包含：

- 可生成课堂 PPT 的结构化课程 Spec。
- 讲师备注，说明每页如何讲、如何追问、如何处理常见偏差。
- 实操任务卡，包含目标、限制、验收标准和安全红线。
- 大作业 Rubric，覆盖文档质量、实现正确性、测试验证、AI 协作过程和安全合规。
- 讲师 Runbook，覆盖课前、课中、课后运营动作。
- 提示词样例，帮助讲师演示“好输入、Review、打回、修复”的过程。

## 内容质量要求

- 每页必须有一个核心判断，避免只有工具功能介绍。
- 每个演示必须展示至少一个人工 Review 或打回修订动作。
- 每个练习必须有可观察的 Done Definition。
- 涉及 Token、MCP、AK/SK、日志、权限的内容必须使用占位符和脱敏表达。
- 对外部或内部工具的名称变化，必须集中修改 Spec，不能只改生成物。

## 生成质量要求

- `npm run validate` 能发现缺失标题、重复 slide id、空模块和不支持的视觉组件。
- `npm run generate` 能稳定生成 Slidev Markdown。
- `npm run build` 能生成静态站点。
- 生成物不得提交到 Git，除非后续明确把某个导出版本作为发布包管理。
