# Proposal: AI 辅助编码实战营课件生产方式

## 背景

AI 工具、内部平台和研发规范会持续变化。如果课件只以 PPTX 形式维护，讲师每次更新都需要手工查找页面、同步口径、修排版，并且难以追踪“为什么这样讲”。本课程采用 Spec Driven Development 思路，把课程事实、教学路径、实操验收和生成规则存放在代码仓库中，需要交付时再生成 Slidev、网页、PDF 或 PPTX。

## 目标

- 让讲师维护结构化 Spec，而不是维护一次性 PPT 文件。
- 让课程内容像代码一样可版本化、可 Review、可校验、可回滚。
- 让 AI 参与课件迭代时有明确上下文、边界和验收标准。
- 让同一套课程源文件支持课堂授课、课前通知、课后作业和团队复讲。

## 非目标

- 不把本仓库作为真实 Token、账号、生产地址或内部密钥的存储位置。
- 不追求生成脚本覆盖所有复杂排版，课程源文件优先保证内容准确和可维护。
- 不把生成出的 PPTX/PDF 作为长期维护源。

## 成功指标

- 讲师修改 `specs/course.yaml` 后，能够用 `npm run check` 生成可预览课件。
- 课程每一页都有明确的学习判断、课堂行为或验收点。
- 每个实操任务都有约束、验收标准和讲师 Review 关注点。
- 课程变更可以通过 Git diff 看清内容变化，而不是比较二进制 PPT。

## 关键风险

- **内容过时**：内部工具名、权限流程或项目仓库变更后，Spec 未及时更新。
- **讲师口径漂移**：不同讲师手工改生成物，导致团队复讲版本不一致。
- **安全泄露**：示例中混入真实 Token、AK/SK、生产地址或个人账号。
- **AI 生成幻觉**：直接让 AI 扩写 PPT 页面，而没有课程目标、受众和验收约束。

## 决策

采用“课程内容 Spec + 生成脚本 + 讲师维护指南”的仓库结构：

- `specs/course.yaml` 是唯一可执行课程内容源。
- `specs/course-production/` 记录本课件工程自身的 SDD 设计。
- `docs/` 存放讲师维护、授课运行和提示词样例。
- `build/`、`dist/`、PPTX、PDF 均为临时生成物，不提交。
