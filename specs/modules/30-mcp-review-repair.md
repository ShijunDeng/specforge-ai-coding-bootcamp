# MCP 提单、代码检视与自动修复

## Module Brief

本模块讲解 CodeHub MCP、代码规范检视 Skill、修复 Skill，并演示故意埋雷、提单、查错、修复。它把工具操作扩展为企业质量闭环和安全边界训练。

## Teaching Design

- **课堂角色**：学员从“本地能跑通”升级为“能让 AI 在企业研发平台里受控行动”。
- **故事冲突**：AI 会写代码还不够，进入团队协作后必须面对 MR、规范检视、Token、审计和修复闭环。
- **讲师演示案例**：在 Petclinic 变更里故意保留 System.out、潜在 NPE 或敏感日志，让机器检视抓住问题，再用修复 Skill 收口。
- **安全道具**：脱敏 Token、演示仓库、演示分支、检视意见截图或预置结果。
- **插图节奏**：先用流程图解释 MCP 手脚，再用检查清单压住权限边界，用任务流展示“埋雷-建单-亮红-修复-验证”。
- **验收证据**：MR 链接、机器检视意见、修复 diff、测试结果和人工 Review 结论。

### Headline
MCP 像平台闸机：AI 可以伸手做事，但每一步都要刷权限卡。

### Body
当 Agent 想创建 MR、触发检视或读取结果时，MCP 负责确认“谁在操作、操作哪个仓库、允许做什么、留下什么审计记录”。


### Example
例如：课堂允许 AI 基于当前演示分支创建 MR 并返回链接，但删除分支、改保护规则、合并到主干这些动作会被权限闸机挡住。

### Key Points
- MCP 不是让 AI 绕过 Git，而是让平台动作可审计、可授权、可复现。
- 每次外部动作都要知道使用哪个账号、哪个仓库、哪个分支。
- 能力越强，越需要人工确认和最小权限。
- 课堂演示只使用脱敏 Token 和演示仓库。

### Headline
能创建 MR 的 Token，不是“课堂小工具”，而是一张平台门禁卡。

### Body
这页不只讲怎么配通，更要让大家看到哪些动作被允许、哪些动作必须被拒绝；权限越靠近平台，就越要脱敏、审计和课后回收。


### Example
例如：课堂 Token 的权限清单应该像门禁白名单：可以创建演示 MR、读取检视结果；不能删除分支、改保护规则、访问生产项目。

### Key Points
- 使用课堂仓库或演示分支，避免误操作生产项目。
- Token 权限只覆盖创建 MR、读取检视、触发必要动作。
- 不在 Prompt、日志、课件、截图中输出完整 Token。
- 课后按企业规范回收或轮换临时授权。
- 操作前检查 Git 状态和远端仓库地址。

mode: talk

### Headline
机器检视像门口安检：先拦住 System.out、NPE 和敏感日志。

### Body
人工 Reviewer 应该花时间判断业务和架构，不应该反复指出 `System.out.println`、弱断言、未判空和密钥日志。机器先拦一轮，人再判断真正难的问题。


### Example
例如：机器能抓住 `System.out.println(owner.getName())` 和 `owner.getPet().getName()` 的潜在 NPE；但“失败是否应该重试、重试几次”仍要人结合业务判断。

### Key Points
- 明确哪些规则适合机器检视，哪些仍需要人工判断。
- 检视意见必须能定位到文件、行、风险和修复建议。
- 修复 Skill 读取意见后生成候选补丁，仍需人工 Review。
- 不接受“修复后没跑测试”的闭环。

### Visual
- 规范类：命名、日志、格式、依赖。
- 风险类：NPE、资源释放、异常吞掉。
- 安全类：敏感日志、密钥硬编码、权限绕过。
- 测试类：缺少边界测试、断言无意义。

### Headline
我们故意埋一颗雷，看它怎样被 MR 检视抓住、修掉、再跑绿。

### Body
演示会把一个看似无害的打印和一个潜在 NPE 放进分支里，然后让平台检视亮红灯；重点不是“犯错”，而是看错误如何变成可执行修复。


### Example
例如：演示中故意留下 `System.out.println(ak)`，机器检视指出敏感日志风险，修复 Skill 应改成脱敏日志并补充测试或说明。

### Key Points
- 埋雷：System.out、潜在 NPE 或敏感日志示例。
- 建单：通过 MCP 指令创建 MR，不手敲远端平台流程。
- 查错：触发检视，拿到清晰、可定位的意见。
- 修复：调用修复 Skill，要求最小 diff。
- 验证：重新运行测试并 Review 修复结果。

### Headline
你必须拿到一次检视意见，并用修复 Skill 处理完成。

### Body
你将在自己的 Petclinic 分支中保留一个明确缺陷，用 MCP 指令建单，主动触发查错，再用修复 Skill 完成闭环。


### Example
例如：你的 MR 至少要有一条机器检视意见、一段修复 diff 和一次修复后测试结果；没有检视意见就不算打通质量闭环。

### Key Points
- 配置个人 MCP，确认远端仓库和分支。
- 制造一个可被规则识别的缺陷。
- 使用 MCP 创建 MR，记录 MR 链接。
- 获取机器检视意见，不手动绕过。
- 使用修复 Skill 修改，并重新运行测试。

### Headline
工程师价值不是亲手完成每个机械动作，而是负责目标、判断和验收。

### Body
第一课打通的 5 个节点是后续复杂项目 SDD 的最小执行单元：写功能、生成单测、MCP 建单、代码检视、自动修复。


### Example
例如：第一课完成后，你已经能把“写功能、补测试、建 MR、查问题、修复验证”串成一条可复制的个人研发流水线。

### Key Points
- 人做决策：定义需求、边界、验收和风险。
- 机器做模板劳动：生成候选代码、生成测试、执行平台动作。
- 人做 Review：判断业务语义、架构一致性和安全边界。
- 机器做反馈循环：根据测试和检视意见修复。
- 证据做沉淀：把流程复制到团队。
